# 山グラフと Heightmap

作成日時: 2026-09-30 12:40
更新日時: 2026-10-03 10:28

## 位置付け

[岩アセットと山グラフ](rock-asset-mountain-graph.md) の M1（山グラフの土台）。岩山（山一つ、一辺 50〜500 m 程度）の下地を、ハイトマップから作る。

## 山グラフ（.mountaingraph）

- 岩グラフ（`.rockgraph`）と同じアプリで扱う。中身は同じ形式（`rock-editor.scene`）で、**拡張子だけが違う**。開いたファイルの拡張子で文書の種類（`Application::DocumentKind`）が決まる。
- 「ファイル」→「新規山グラフ」で作る。最初は `Heightmap（ノイズの山）→ Mesh Output`、`Surface（Triplanar、4 m ごと）→ Mesh Output の Material` の 3 つのノードで、カメラは山全体が見える所（約 330 m 離れた所）に置く。「新規シーン（岩グラフ）」（Ctrl + N）は今までどおり。
- アセット欄の右クリック（何も無い所）の「岩グラフを作成」「山グラフを作成」でも作れる。表示中のフォルダに「新規岩グラフ.rockgraph」「新規山グラフ.mountaingraph」（同名があれば番号付き）を作って開き、新しい文書を描いてから（数フレーム後、評価が終わってから）保存する。今の文書を閉じるので、「シーンの切り替え」の確認（保存するか）を通す。
- 保存は `.mountaingraph`（ルートの中）。「シーンを開く…」、アセット欄のダブルクリック、ドラッグ＆ドロップ、最近使ったシーンから開ける。アセット欄では「山グラフ」と表示する。
- 右クリックメニューは文書の種類で分ける。山グラフには「地形」（Heightmap）、「共通」（Merge / Mesh Output）、「材質」（Surface / Apply Material / 各マスク / Material Bake）を出す。岩を作るノード（ボリューム・ピース・モデルなど）は岩グラフにだけ出す。コピー＆ペーストでは種類を問わず貼れる。

### 地形を Mesh として扱う判断

2026-09-30 のユーザー確認により、設計資料にあった専用の型（Heightfield / Terrain / Terrain Mask）は作らず、**地形を UV 付きの Mesh として下流へ渡す**。地形の格子にはハイトマップと同じ UV が自然に付くので、既存の次のノードがそのまま使える。

- Shape Mask: 上向き度（= 傾斜）、高さ、曲率（谷・尾根）、遮蔽のマスク
- Mask Combine / Mask Filter / Noise Mask / Deposition Mask
- Apply Material / Surface / Material Bake
- Mesh Output

M2 の Rock Scatter も「Mesh（地形）と Mask を受けて撒く」形にする。

## Heightmap ノード

入力なし、出力は UV 付きの Mesh。種類を選ぶ 1 つのノード（ノード設計の方針）。

| 項目 | 内容 |
| --- | --- |
| 種類 | ノイズ / 画像 |
| 幅・奥行き (m) | X と Z の長さ。既定 200 m 四方（1〜10000） |
| 最低・最高の高さ (m) | ハイトマップの 0（黒）と 1（白）に当てる高さ。既定 0〜80 m |
| 格子の細かさ | 格子の一辺の分割数（16〜1024、既定 256）。三角形数は 2 × 細かさ²（256 で約 13 万） |
| テクスチャ解像度 | UV のアトラス寸法（128〜4096、既定 1024）。Shape Mask や Material Bake の画像の大きさの基準 |
| Seed・起伏の大きさ・荒さ・山の形 | ノイズのとき。起伏の大きさはいちばん大きな起伏（m、既定 60）。荒さは細かい起伏の強さ（0〜1）。山の形は 1 で中央が高く縁が低い 1 つの山、0 で一様な起伏（既定 0.8） |
| 画像 | 画像のとき。「画像を選ぶ…」で選ぶ |

保存名は `heightmap`。保存・読込と Undo / Redo に対応。画像のパスはシーンからの相対パスで保存する。評価は別スレッドで行い、設定と（画像なら）ファイルの大きさ・更新時刻をキャッシュのキーにする（画像を描き直せば読み直す）。

### 地形のメッシュ

- 中心が原点。X が幅、Z が奥行き。ハイトマップの上（行 0）が奥（-Z）、左が -X。
- 格子の点の高さはハイトマップを双線形で読む（格子の細かさと画像の大きさは別に決められる）。
- どの面も上（+Y）を向く。**閉じていない**（縁で切れた面）ので、閉じたメッシュを前提にする Decimate / Remesh / To Volume には渡せない。
- UV は 1 枚の島（u が +X、v が +Z、0〜1）。`uvWidth` / `uvHeight` はテクスチャ解像度。

### ノイズの山

値ノイズの fBm（6 段）に、中央が 1・縁が 0 のドームを混ぜる。山の形が 1 なら起伏はドームの上にだけ乗り、0 なら一様な起伏。最後に最低〜最高を 0〜1 へ伸ばす（最低が「最低の高さ」、最高が「最高の高さ」になる）。

### 画像のハイトマップ

`LoadHeightImage`（`core/ImageIo`）で最初のチャンネルを 0〜1 として読む。

- **16bit PNG**（推奨）: 0〜65535 を 0〜1 に。
- 8bit の画像（PNG / TGA / BMP / JPG）: 0〜255 を 0〜1 に。段が見えやすい。
- **EXR**: 値をそのまま使い、0〜1 を外れていれば最低〜最高を 0〜1 へ伸ばす。

## 制限

- 地形の LOD は無い（山一つの規模なので、格子の細かさで調整する）。1024 にすると約 210 万三角形。
- 画像の読み込みは評価のたびに行う（キャッシュが当たれば読まない）。大きな画像では最初の評価に時間がかかる。
- ノイズは簡単な値ノイズで、浸食などの地形らしさは無い。本格的な地形は terrain-graph で作ってハイトマップを書き出し、画像として読む。

## 検証

`tests/TerrainTests.cpp`。ノイズの高さが 0〜1 に伸びていること、Seed での再現と違い、山の形で中央が高いこと、格子の点と三角形の数、実寸と中心、面の向き、UV、設定の検査、EXR（範囲を伸ばす）と 8bit PNG の読み込み、グラフでの評価（ノイズ・画像・画像未選択の診断）、Shape Mask（上向き度）を地形に使えることを確認する。

実アプリ（RelWithDebInfo）では `examples/mountain/` を開き、ノイズの山の表示、Shape Mask を選んだときの傾斜のマスク、保存 → 読み込み → 保存でのグラフの一致を確認した。別に作った 16bit PNG（2 つの峰）を画像として読み、段の無い表示と、保存したときのシーンからの相対パスを確認した（`build/rock-asset-validation/`）。「新規山グラフ」のメニュー操作と、画像を選ぶダイアログは実マウスで未確認。

## 地形の加工（2026-10-03 追加）

Heightmap の出力は、評価結果にハイトの格子（`GeneratedRock::terrain`）と寸法を持つ。[Terrain Erode / Terrain Deform](terrain-erode.md) はこの格子を加工してメッシュを作り直す。格子を持たないメッシュ（Base Shape など）は地形のノードに受けられない。
