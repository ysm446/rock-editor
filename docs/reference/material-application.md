# 素材の適用と形状AO

作成日時: 2026-09-21 23:01
更新日時: 2026-09-27 00:32

## 接続

```text
Mesh → UV Unwrap → Apply Material → Apply Material → Material Bake → Mesh Output
                       ↑                 ↑   ↑
                    Surface          Surface Material Mask
```

Apply MaterialはMesh / Material / Maskを入力し、素材情報を持つMeshを出力する。マスク未接続なら全面を今回の素材に置き換える。接続時は白で今回の素材、黒で上流の素材、中間値で線形混合する。先に素材を付けずマスクだけ使った場合、下地は中立の灰色になる。Surfaceを無効にした段は上流をそのまま通す。

同じノードをつないで最大8段まで重ねられる。上限は全面置換でリセットされる。SurfaceごとのUV/Triplanar、投影サイズ・回転・オフセット、チャンネル指定を保持する。法線はワールド空間で混合して正規化し、ベイク時にUV接線空間へ戻す。プレビューとベイクは同じ素材評価・合成処理を使う。

Triplanar素材はUVなしでも表示でき、UV Unwrapを素材適用の後ろへ置くこともできる。UV Unwrapは同じ素材構成の枝を1枚のアトラスへまとめて素材を引き継ぐ。異なる素材の枝をまとめて展開する機能は対象外で、その場合は先にUV Unwrapを通してから素材を適用する。

形状をボリュームへ変換すると素材情報は引き継がない。素材適用はVolume to Meshなどの形状加工の後段へ置き、Material Bakeは素材を重ね終えた後に置く。既存Mesh Output / Material BakeのMaterial入力は互換用に残し、接続した場合は上流の適用情報を全面置換する。

## ハイトで合成（Apply Material の設定）

「ハイトで合成」を有効にすると、マスクを基準に、この素材のハイトが下地より高い所を前に出す（道路のレイヤーの「ハイトで競合」と同じ）。石の隙間に砂が溜まる、苔が凹みに入る、といった合成になる。

- `d = (この素材のハイト − 下地のハイト) × 0.5 + 0.5`（等しければ 0.5）
- `重み = saturate((d − (1 − マスク)) / なだらかさ + マスク)`
- マスク 0 は必ず 0、マスク 1 は必ず 1。マスク 0.5 でハイトが等しければ 0.5。「なだらかさ」（0.01〜1、既定 0.2）が小さいほど、ハイトの差でくっきり分かれる。
- Mask 未接続は全面置換なので効かない。ハイトだけで合成したいときは、定数 0.5 の Material Mask をつなぐ。
- プレビュー・ベイク（同じシェーダ）・Displace の合成ハイト（CPU、同じ式）に効く。保存名は `applyMaterial.heightBlend` / `heightBlendRange`。

## 不透明度（Apply Material の設定）

「不透明度」（0〜1、既定 1）は、この段の素材の効き具合。薄くかけたいときに下げる。

- `最終の重み = マスク（ハイトで合成した後） × 不透明度`。0 で効かない、1 で従来どおり。
- Mask 未接続かつ不透明度 1 は従来どおり全面置換（8段の上限もリセット）。不透明度が 1 未満なら置換せず、上流の素材の上に一様に重ねる。上流に素材がなければ中立の灰色に重ねる。
- プレビュー・ベイク（同じシェーダ）・Displace の合成ハイト（CPU）に効く。保存名は `applyMaterial.opacity`。1 のときはベイクの指紋を変えない。

## Material Mask

- 画像なし：0〜1の定数。
- 画像あり：画像のリニアRチャンネル × 値。白黒画像だけでなく、カラー画像のRも使える。
- 反転：値・画像の強度を掛けた後に `1 - mask`。
- UV / Triplanarを選択。TriplanarはワールドのXYZへ投影し、面の向きで混合する。
- 反復幅：UV時はUV単位、Triplanar時はメートル。

画像はアセットから取り込んで設定欄で選ぶ。UV画像で島ごとの塗り分けをしたい場合は、UV Unwrap後の配置に合わせた画像を指定する。形状から作るマスク（オクルージョン / 上向き度 / 高さ）は [Shape Mask](shape-mask.md)。同じ Mask 入力へつなぐ。ノイズ生成のマスクはまだ含まない。

## Material Bakeの形状AO

「形状AOをベイク」を有効にすると、UVの各画素の表面位置からコサイン重み付き半球へレイを飛ばし、同じ入力メッシュによる遮蔽を求める。三角形BVHで交差判定を高速化し、面の法線方向へ微小なオフセットを置いて自己交差を避ける。素材のNormal/Heightは遮蔽物の形状としては扱わない。

`出力AO = 素材の合成AO × (1 - AO強度 × 遮蔽率)`

| 設定 | 内容 |
| --- | --- |
| 形状AOをベイク | 既定OFF。既存シーンの動作を維持 |
| AO距離 | 遮蔽物を探す距離、0.001〜1000m、既定0.5m |
| AO強度 | 0〜1、既定1。0なら素材AOを保持 |
| AOサンプル数 | 8〜128、既定32 |

BaseColorへ影は書き込まず、既存のRoughnessMetallicAO.pngのBへ合成する。生成したUV素材を表示するとAOが反映される。ベイク前のプレビューは素材が持つAOのみ。

計算対象はベイク入力のメッシュであり、別のMesh Outputや天球・ライトは遮蔽物に含めない。形状AOの画素レイ判定はDirectX 12のCompute Shaderで実行し、DXR専用ハードウェアは要求しない。空間とUVのBVH構築はCPUで行う。128×64画素のタイルをフレーム間で分割処理し、完了タイル数に基づく進捗率とキャンセルボタンを表示する。材質のGPUベイク、BVH準備、最終PNG保存は同期処理。解像度とサンプル数を増やすほど待ち時間が増えるため、まず512・16〜32サンプルで確認する。最大アトラス4096、画像は既存と同じ8bit PNG。計算中にドキュメントや入力が変更された場合は結果を破棄し、完了時にも指紋を再検証する。キャンセル時は既存のベイク画像・材質を保持する。GPU処理に失敗した場合はエラーを表示する。

開発用の `rock_editor.exe --test-gpu-ao` で、実GPU上の結果とCPU参照実装、距離・強度・サンプル数、タイル境界、進捗、部分実行の破棄と再利用を検証できる。

素材・マスク画像・投影・AO設定・形状・UVを変更すると、古いベイクは再ベイク待ちになる。保存/再読込で素材・画像参照とAO設定を復元し、Undo/Redoは適用設定とベイク結果を戻す。指紋形式の更新により、以前の版で作ったベイクは再実行が必要になる場合がある。
