# Decimate

作成日時: 2026-09-22 04:10
更新日時: 2026-09-22 23:50

## 位置付け

形をできるだけ保ったまま Mesh の三角形を減らすノード（ポリゴンリダクション）。入力・出力とも Mesh 型。UV Unwrap の前に置く。

```text
… → Volume to Mesh → Decimate → UV Unwrap → Apply Material → Material Bake
```

Volume to Mesh の出力は格子のセル数で三角形の数が決まり、平らな面にも細かい三角形が並ぶ。UV Unwrap の時間はほぼ三角形の数で決まるので、先に減らすと大きく速くなる。右クリックメニューの「メッシュ（ポリゴン）」にある。

| 入力 6.4万三角形（解像度96、Dual Contouring） | Decimate | UV Unwrap |
| --- | --- | --- |
| 減らさない | — | 17.0 秒 |
| 目標 20,000 | 0.10 秒 | 3.6 秒 |
| 目標 10,000 | 0.10 秒 | 1.2 秒 |
| 目標 5,000 | 0.11 秒 | 0.6 秒 |

Release での実測（`data/test/claude-session-2026-09-22/debug/uv_timing.cpp`。形のずれの上限は既定の 0.004）。

## 設定

| 項目 | 内容 |
| --- | --- |
| 目標の三角形数 | 64〜500,000、既定 10,000。入力がこれ以下なら何もしない。入力が複数のメッシュなら、もとの三角形数に応じて割り振る |
| 形のずれの上限 | 形の最長辺に対する比。0〜0.1、既定 0.004。これを超える縮約はしないので、目標に届かないことがある。0 なら上限なしで目標まで減らす |
| 稜線の保護 | 0〜10、既定 1。折れ角が40度を超える辺を動かしにくくする。0 で保護なし |

保存名は `decimate`。保存・読込と Undo / Redo に対応。設定欄に実際の出力の三角形数を出し、目標に届かなかったときはその旨を表示する。評価は別スレッドで行い、計算中は進み具合を表示する。途中でキャンセルできる。

## 処理

QEM（Quadric Error Metrics、Garland & Heckbert）による辺の縮約。自前の実装で、外部ライブラリは使わない。

1. 座標を最長辺 1 へ正規化する（誤差の比較と行列の条件を寸法に依らなくするため）。
2. 各頂点に、まわりの面の平面までの距離の二乗和を表す行列を持たせる。面積で重み付けする。折れ角が40度を超える辺には、辺を含んで各面に垂直な平面を足し、稜線に沿ってしか動けなくする。
3. 全ての辺について、2頂点を1点へまとめたときの誤差と最適な位置を求め、優先度付きキューへ入れる。最適な位置が求まらない（行列が特異に近い）か、辺から遠く離れるときは、両端と中点から選ぶ。
4. 優先順位の小さい縮約から実行する。優先順位は「誤差 + 辺の長さの二乗 × 小さな係数」。平らな場所ではどの縮約も誤差が 0 になり順序が決まらないので、短い辺から縮約して三角形の大きさを揃える。形のずれの判定には、この項を含めない。
5. 縮約のたびに、次の検査を通ったものだけを実行する。
   - **リンク条件**: 辺の両端が共有する隣接頂点が、辺を挟む2面の向かいの頂点の2つだけであること。満たさない縮約は非多様体を作る。
   - **向かいの頂点の面が4枚以上**: 3枚以下だと、縮約で面2枚だけの潰れた袋ができる。四面体もここで守られ、連結成分が消えない。
   - **面が裏返らない**: まわりの面の法線が、縮約の前後で約78度以上変わらないこと。面積のない面も作らない。
   - **細長い三角形を作らない**: 形の良かった場所（面積の2倍 ÷ 最長辺の二乗 が 0.05 以上）に、それ未満の三角形を作る縮約は断る。細長い三角形は UV 展開で縮退する。Marching Tetrahedra のメッシュのように、もとから細長い面がある場所は自由に動かす。
6. 目標に達するか、実行できる縮約が無くなったら終える。形のずれは `sqrt(誤差 ÷ 重みの合計)` で測り、上限を超える縮約は捨てる（誤差は増える一方なので、後でも使えない）。

出力は `InspectMesh` で検証し、閉じていること・体積が正であること・連結成分の数が入力と同じであることを確かめてから返す。満たさなければエラーにして、壊れたメッシュを下流へ渡さない。動かしていない頂点は、入力の座標をそのまま使う。同じ入力から同じ結果を得る（同じ優先順位は頂点番号で順序を決める）。

## 診断

| 状況 | 表示 |
| --- | --- |
| 入力が未接続 | Mesh出力を接続してください |
| Volume / Model を接続 | Mesh入力が必要です / 生成メッシュが必要です |
| 開いたメッシュ、内向きのメッシュ | 閉じた、外向きの面を持つMeshが必要です |
| 400万三角形を超える入力 | Decimate の入力は400万三角形までです |
| 設定が範囲外、または非有限 | それぞれの範囲を示す |
| 結果が閉じた形にならない | 三角形を減らした結果が閉じた形になりませんでした… |

## 制限

- **細部は消える。** Volume Noise の細かい凹凸や細い割れ目は、面数を減らすと失われる。消えた細部を法線で戻すには、縮約前のメッシュから縮約後のメッシュへ法線を焼く処理（High → Low のベイク。[設計メモ](rock-shaping-nodes.md) の 7）が要る。未実装。
- **展開済みのUVを保持する。** 島IDやコーナーUVの不連続な頂点を固定し、島内部の辺上で位置とUVを同じ比率で補間する。UVの反転・退化を起こす縮約は拒否する。アトラス寸法と島IDを保持し、再配置はしない。境界が多いと目標まで減らせない。曲面や非線形なUVでは模様の歪みが残る場合があり、完全な見た目の一致を保証するものではない。
- 材質の割り当て（Apply Material）は引き継ぐ。直方体の集まりという由来（To Volume の解析的な高速経路）は引き継がない。
- 目標は上限であり、保証ではない。形のずれの上限と上の検査により、目標より多く残ることがある。
- 減らした後の面は平らに見える（スムーズシェーディングの折れ角40度を超える面が増えるため）。
- 面の向きで重みを変える、特定の領域を保護する、といった制御は無い。

## 検証

`tests/DecimateTests.cpp`。球（12,288三角形）を 2,000 へ減らして、閉包・1成分・目標への到達・オイラーの関係（V = F/2 + 2）・体積と表面の位置・UVなしの入力はUVなしのままであること・再現性を確認する。ほかに、入力が目標以下なら何もしないこと、形のずれの上限で手前に止まること、格子から作った立方体が 1/20 未満まで減って体積と外接範囲を保つこと、64枚まで減らしても角と体積を保ち針のような三角形を作らないこと、2成分のどちらも消さないこと、進捗が単調で結果を変えないこと、キャンセル、不正な設定と入力7種の拒否を確認する。下流への接続として、ノイズ付きの塊（2.7万三角形）を 6,000 へ減らし、体積を保ち、UV 展開と再ボリューム化へ渡せることを確認する。グラフでは型制約、未接続の診断、Marching Tetrahedra のメッシュが半分未満に減ること、UV Unwrap へ渡ること、設定変更による作り直しを確認する。

展開したBoxを細分化した入力で、削減後のUV有効性、島ごとの面積と向き、位置とUVの対応、アトラス寸法、削減不要時の保持、不正UVの診断を検証する。グラフではUV Unwrap → Apply Material（Shape Maskで2素材）→ Subdivide → Decimateでレイヤー・マスク画像・UVが維持されることを確認する。
