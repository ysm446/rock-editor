# Volume to Mesh の変換方式

作成日時: 2026-09-21 17:04
更新日時: 2026-09-21 22:22

## 方針

同じ `VolumeGrid` から、従来の Marching Tetrahedra と Dual Contouring を選べるようにする。ノードの初期値と旧シーンの動作は従来方式。上流の直方体や解析関数に戻らず、入力されたSDFだけを使う。描画のスムーズシェーディングは両方式に共通で、メッシュ抽出とは別の設定。

## 共通のSDFプレビュー

「プレビュー設定 → SDFプレビュー（共通）→ 変換方式」で、Volume を直接表示する際の方式を選ぶ。To Volume / Volume Transform の出力ピンと、Volume を直接接続した Mesh Output に共通で適用する。Volume to Mesh を通した結果は、そのノードの方式に従う。

共通設定はアプリの `display.sdfPreviewMethod` に保存する。既定は Marching Tetrahedra。シーンのデータや Undo 履歴には含めない。切り替え時は内部SDFを再利用し、方式を含む外皮キャッシュの判定により表示用メッシュを再生成する。To Volume の解像度は引き続き内部グリッドの細かさを指定する。

## Dual Contouring の実装


基本となる交点・法線のQEFと双対接続は [Juほか, Dual Contouring of Hermite Data (2002)](https://www.cs.rice.edu/~jwarren/papers/dualcontour.pdf) を参照。原論文の適応八分木・簡略化は実装していない。

- 格子辺の符号変化から交点を線形補間し、そのセルのトリリニア補間の解析的勾配を正規化して法線とする。正確な元形状の交点・法線ではなく、SDFの格子からの推定値。
- セル寸法を1に正規化してQEFを解く。平面・稜線で不定となる方向には交点重心への弱い正則化（1e-5）を使う。セル内の自由/下限/上限の27通りを解き、残差が最小の頂点を選ぶ。セル境界から1e-4だけ離して隣の頂点との完全一致を避ける。
- 面上の交点をつないでセル内の表面を分け、表面ごとに頂点を配置する。面の符号が交互になる曖昧な配置では、双一次補間の鞍点の符号で隣のセルと同じ接続を選ぶ。
- 曖昧な共有面では輪郭ごとの中間点を面上に配置し、隣接セル間で共有する。同じセル頂点の組に2本の輪郭がつながる場合も、1辺へまとめず別の接続として保持する。該当する四角形は中心点を加えて三角形化し、その他は従来のQEF頂点・対角線分割を維持する。
- 符号が変わる各格子辺を囲む4セルの頂点をつなぎ、曖昧な共有面を含まない場合は短い対角線で2三角形に分割する。面の向きは格子辺の内外から決める。
- 表面抽出の後は従来方式と共通の検証で、不正値・縮退面・閉包・正の体積・分離した外皮を確認する。失敗した場合はエラーにし、他方式へ黙って切り替えない。

## 保存と互換性

```json
"volumeToMesh": { "method": "dualContouring" }
```

もう一方の値は `marchingTetrahedra`。設定なし・未認識の保存名は従来方式で読む。方式を枝キャッシュのキーへ含めるため、変更時は下流のメッシュを再生成する。上流のSDFは再利用できる。ノード設定は既存のスナップショットに入り、Undo/Redoで復元する。

## 現状の制約と比較

- 格子で失われた細部は復元できない。回転の再サンプル後では、その近似誤差も引き継ぐ。直線の稜線が必ず完全な直線になるという保証はない。
- セル程度の小さな穴・接続は両方式でトポロジーが変わる場合がある。最大設定の回帰ケースでは従来方式2成分、Dual Contouring4成分（どちらも外皮1つと内部空洞）。明確な球殻では両境界と解析体積を検証する。
- 出力は三角形メッシュ。一般的な自己交差の検出・修復、適応格子、ポリゴン削減は未対応。
- `examples/volume-transform` の同じ解像度48のシーンで、実画面の三角形表示は従来方式222,561、Dual Contouring72,161（画面内の描画統計）。瞬間FPSは性能の比較値として扱わない。

画像と保存往復の検証素材は `build/dual-contouring/validation/`。使い方と制限は [直方体とボリューム](box-volume.md)、同じ入力を持つ比較シーンは [サンプル](../../examples/volume-meshing/README.md)。
