# 岩アセットと山グラフ（設計メモ）

作成日時: 2026-09-30 06:08
更新日時: 2026-09-30 08:55

## 目的

岩山（山一つ）を、ゲームで使える形で組み立てる。山の形のメッシュを作り、その表面に沿って岩のインスタンスを並べる。

そのため、今の 1 種類のシーンを役割で 2 つに分ける。

- **岩グラフ**: 今の `.rockscene`。岩の形と材質をノードで作り、LOD を段階的に持つ**岩アセット**を焼いて持つ。岩アセットは岩グラフに含まれ、別のアセットとしては書き出さない。
- **山グラフ**: 新しいファイル。ハイトマップから山の下地を作り、マスクで決めた場所へ岩アセットのインスタンスを撒く。

山グラフは `.rockscene` を直接参照する。ただし岩グラフを評価し直すことはせず、岩グラフが焼いて持っている岩アセット（メッシュとテクスチャ）を読み込むだけにする。

この資料は計画段階の設計で、どれも**未実装**。実装順と現在地は [plan](../plan/plan.md) と [progress](../plan/progress.md) を正とする。

## スケール

- 対象は**山一つ**。一辺 50〜500 m 程度を想定する。数 km の地形は対象にしない（それは terrain-graph の役割）。
- 岩の数は、1 つの山で数百〜数千個。
- 単位は m、座標系は今と同じ右手系 Y-up。

この規模なら、地形の LOD、インポスター、GPU による大量カリングは要らない。岩アセットの LOD と GPU インスタンシングがあれば足りる見込み。

## 全体の流れ

```text
[岩グラフ .rockscene]                              [山グラフ（新しいファイル）]
 形 → 材質 → UV → Material Bake                     Heightmap → 下地メッシュ
   → Rock Asset ──焼く──> 岩アセット ──参照・読込──> Rock Scatter ← マスク（傾斜・高度・曲率）
                   （岩グラフの一部。変種 × LOD）         → 表示（インスタンシング）
                                                          → （後続）HLOD の焼き込み・書き出し
```

## 岩アセット

### 中身

| 項目 | 内容 |
| --- | --- |
| 変種 | 1 つの岩グラフから Seed を変えて N 個作った岩。変種ごとに形・UV・テクスチャが違う |
| LOD0〜LODn | 変種ごとの段階的なメッシュ。既定は 100% / 50% / 25% / 12% の 4 段。最終段は 50〜200 三角形程度 |
| テクスチャ | LOD0 の UV で焼いたもの（BaseColor / Normal / RoughnessMetallicAO / Height）。**全 LOD で共有する** |
| 切り替え基準 | 段ごとの画面上の大きさ（画面の高さに対する比）。距離ではなく大きさで決め、倍率を変えて置いても同じ基準で効くようにする |
| ピボットと境界 | 底面の中心と境界ボックス。配置やめり込み量の基準にする |
| 焼いたときの状態 | 変種の Seed、焼いたときのグラフと設定のハッシュ。グラフが焼いた後に変わったかを判定するのに使う |

### 置き場所

2026-09-30 のユーザー判断で、岩アセットは**岩グラフに含める**。別のアセット（`.rockmodel` など）として書き出さない。岩グラフと岩アセットを二重に管理しなくて済み、焼いた結果が古いかどうかも同じファイルの中で判定できる。

- 設定（変種の数、LOD の段、切り替えの大きさ、焼いたときのハッシュ）は `.rockscene` に保存する。
- メッシュとテクスチャは大きく、JSON に入れると重くなり差分も読めなくなるので、同名の付属フォルダ（例: `foo.rockscene` の横の `foo.rockscene.bake/`）に置く。アプリはこのフォルダを岩グラフの一部として扱い、保存・名前の変更・コピー・削除のときに一緒に扱う。メッシュの形式は A1 で決める（候補は独自のバイナリか glTF）。
- 付属フォルダが無い・壊れている場合は「未焼成」として扱い、岩グラフを開けば焼き直せる。
- 既存の Model ノードでも `.rockscene` を選んで置けるようにする（LOD0 を出す）。今の `.rockmodel`（FBX の取り込み）はそのまま残す。
- 項目の名前と意味は terrain-graph の `.tgmodel`（LOD の `lodDistances` を持つ）とできるだけ揃える。ゲームエンジンや terrain-graph へ持ち込むための書き出し（FBX / glTF）は、後続の別機能とする。

### Rock Asset ノード（旧案の名前は Asset Output）

2026-09-30 に LOD の生成とビューポートでの切り替えまでを実装した。仕様は [Rock Asset](rock-asset.md)。付属フォルダへ焼いて保存する部分と変種は未実装。以下は計画段階の記述。

岩グラフの末端に置き、この岩グラフの岩アセットを決めるノード。1 つの岩グラフに 1 つだけ置ける。ノード設計の方針（明示的な入力ピン、種類を選ぶ汎用ノード）に合わせる。

- 入力: Mesh（UV と Material Bake の結果が付いたもの）。
- 設定: 変種の数、LOD の段数と各段の割合、各段の切り替えの大きさ、テクスチャの解像度。
- 「岩アセットを焼く」ボタンで焼き、付属フォルダへ保存する。重いので別スレッドで行い、進み具合を固定欄に出してキャンセルできるようにする（全ノード共通の方針）。
- 焼いた後にグラフが変わると「焼いた結果が古い」と固定欄に出す。自動では焼き直さない（重いため）。

### 変種（Seed）

今の Seed は、Random Boxes・Volume Noise・Voronoi 分割などのノードがそれぞれに持っている。変種を作るため、**グラフ全体の Seed のずらし量**を加える。

- 変種 i を評価するときは、Seed を持つすべてのノードで Seed に i（をハッシュで混ぜたもの）を足す。
- グラフそのものは書き換えず、評価の入力として渡す。普段の編集ではずらし量 0 で、今と同じ結果になる。
- 変種ごとに Material Bake まで評価し直すので、時間は変種の数に比例する。

### LOD の作り方

全 LOD でテクスチャを共有するには、**UV の継ぎ目と属性を保つ簡略化**が必要になる。（当初「今の Decimate は UV の継ぎ目を保たない」と書いたのは誤りで、Decimate は展開済みの UV を島の境界を固定して保てた。ただし境界に触れる縮約を全て断っていたので、島の多い岩では細かい段が目標に届かなかった。2026-09-30 に継ぎ目に沿った縮約を足して解消し、候補 2 を採用した。）

- 候補 1: meshoptimizer の `meshopt_simplifyWithAttributes`（vcpkg にある）。継ぎ目の頂点を固定し、UV・法線を誤差に含めて減らせる。
- 候補 2: 自前の QEM（Decimate）に UV の継ぎ目の保護と属性の誤差を足す。
- 2026-09-30: 候補 2（自前の Decimate の改良）を採用。meshoptimizer は、自前の結果で足りなくなったときに改めて比べる。
- LOD1 以降の法線は LOD0 で焼いた法線マップで補う。High → Low の法線の転写（[設計メモ](rock-shaping-nodes.md) の 7）は、LOD0 を Remesh / Decimate で作る場合に後から検討する。

### 古くなったアセットの扱い

焼いたときのハッシュと、岩グラフの今のハッシュを比べる。岩グラフの中では Rock Asset の固定欄に、山グラフでは Rock ノードに「焼いた結果が古い」と印を出す。山グラフからも、ボタン 1 つで岩グラフを裏で読み込んで焼き直せるようにする。自動では焼き直さない（重いため）。古いままでも、最後に焼いた結果で表示は続ける。

## 山グラフ

### ファイルとアプリ

- 拡張子の案は `.rockmountain`。岩グラフと同じアプリで、開くファイルによってグラフの種類を切り替える。
- ノードエディタ、プロパティ、ビューポート、アセット欄、保存、Undo は今の仕組みを共用する。ノードの一覧（右クリックメニュー）はグラフの種類ごとに分ける。
- Rock ノードからは、元の岩グラフを開けるようにする。

### 構成

2026-09-30 のユーザー判断で、山グラフは**複数の岩グラフを読み込む**。岩グラフ 1 つを 1 つの Rock ノードとして置き、Scatter 系のノードへピンでつないで山に撒く。岩の一覧を Scatter の設定の中に持たせないので、どの岩がどの配置に使われているかがグラフで見える（明示的な入力ピンの方針）。

```text
[Rock: cliff_a.rockscene] ─┐
[Rock: cliff_b.rockscene] ─┼→ Rock Scatter（大）─────────────────┐
[Heightmap]→[Terrain Mesh]─┤    ↑ Mask（傾斜）                    │
                           │                                       ├→ Instance Merge → Mountain Output
[Rock: boulder.rockscene] ─┼→ Rock Scatter（中）← 避ける ←（大の結果）│
[Rock: pebble.rockscene] ──┴→ Rock Scatter（小）← Mask（窪み）──────┘
```

（地形の線は図を簡単にするため一部省いた。Scatter はどれも Terrain Mesh を受ける。Mountain Output も地形を受ける。）

### 型

| 型 | 中身 |
| --- | --- |
| Heightfield | ハイトマップの格子と実寸 |
| Terrain | 下地のメッシュ（Heightfield から作る）と材質 |
| Terrain Mask | 地形の上の 2D のマスク（0〜1）。Heightfield と同じ範囲 |
| Rock | 焼いた岩アセットへの参照と、使う変種・倍率・重み |
| Instances | 岩のインスタンスの一覧（岩・変種・行列） |

### ノード

| ノード | 入力 | 出力 | 役割 |
| --- | --- | --- | --- |
| Heightmap | なし | Heightfield | 画像（16bit PNG / EXR）を読み、実寸（幅・奥行き・高さ）を与える。まずは読み込みだけ。後で簡単な生成（ノイズ）を足すかもしれない |
| Terrain Mesh | Heightfield | Terrain | 下地のメッシュを作る。格子の細かさを選ぶ。材質は今の Surface / レイヤーマテリアルを使う |
| Terrain Mask | Heightfield | Terrain Mask | 種類（傾斜・高度・曲率）を 1 つのノードの中で選ぶ（Shape Mask と同じ作り方）。合成と加工は Mask Combine / Mask Filter の考え方を地形マスクへ持ち込む |
| Rock | なし | Rock | `.rockscene` を 1 つ選ぶ。焼いた岩アセットを読む |
| Rock Scatter | Terrain、Terrain Mask（任意）、Rock（可変本数）、避ける Instances（任意） | Instances | 岩を撒く |
| Instance Merge | Instances（可変本数） | Instances | 複数の Scatter の結果をまとめる |
| Mountain Output | Terrain、Instances | なし | 表示と書き出しの末端 |

terrain-graph にある Heightmap・地形マスク・ModelScatter の実装を参考に移植する。ただし terrain-graph は数 km の地形向けで GPU の compute で評価しているので、山一つの規模に合わせて簡単にしてよい。

可変本数の入力ピンは、今の Merge ノードと同じ仕組み（つなぐたびに空きのピンが 1 本増える `NormalizeVariablePins`）を使う。

### Rock

- 設定: `.rockscene` のパス、使う変種（全部 / 選んだものだけ）、倍率、重み（Scatter の中でどの岩をどれだけ選ぶか）。
- 選ぶと、使う変種をビューポートに並べてプレビューする（選択時プレビューの方針）。
- 焼いた結果が古い・無いときは印を出し、「焼き直す」ボタンを置く（上の「古くなったアセットの扱い」）。
- 同じ `.rockscene` を複数の Rock ノードで読んでも、焼いた結果はパスでキャッシュして 1 回だけ読み込む。同じ岩を崖には大きく、麓には小さく撒くといった使い回しは、Rock ノードを分けても 1 つの Rock を複数の Scatter につないでもよい。

### Rock Scatter

大・中・小の大きさの階層は、Scatter ノードを分けて表す。階層ごとにマスクと岩の組み合わせを自由に変えられる。

- 密度: 間隔（m）で指定する。目安は、表面積を A、1 個が覆う面積を a、重なりの係数を k（1.3〜2）として N ≈ k·A/a。大きさが半分になるごとに数を 4〜6 倍にすると自然に見える（べき分布）。
- 配置: 表面へのポアソンディスク。マスクの値で密度を下げる。
- 岩の選び方: 入力の Rock の重みで選ぶ。後で傾斜と曲率で重みを変える設定を足す（急斜面は縦長の崖用、緩斜面は平たい岩）。
- 倍率の範囲（Rock の倍率に掛ける）。
- 向き: 法線への合わせ込みの強さと、**層の向き**（全体で揃える傾き）。地層の向きを揃えると岩場らしくなる。
- めり込み: 境界ボックスに対する比で下地へ沈め、接地の継ぎ目を隠す。
- 避ける: 入力した Instances の岩の境界（球か箱）と重なる点を捨てる。大を先に撒き、中は大を避ける、という順序をピンで表す。
- Seed。

評価は Seed から毎回決まるので、保存はグラフの設定だけでよい。インスタンスを手で動かす・消す機能は後続とし、そのときに個別の上書きの保存方法を決める。

### 後で足す候補

- **インスタンスから作るマスク**: 大きい岩の足元をマスクにし、小石を溜める（崖錐）。
- **Instance Filter**: 範囲や条件でインスタンスを消す、一部を手で動かす（Piece Select / Piece Filter に似た役割）。
- **傾斜と曲率による岩の選び分け**: Rock Scatter の中の重みの変調。

### 表示

- **GPU インスタンシング**: 今のモデル描画（`ModelInstanceDraw`）は 1 個ずつ描く。岩アセット × 変種 × LOD ごとにまとめ、インスタンスの行列をバッファで渡して一度に描く経路を足す。
- **LOD の選択**: インスタンスごとに画面上の大きさを求め、段を選ぶ。数千個なので初版は CPU で毎フレーム計算してよい。
- **小さい岩を消す**: 画面上で数ピクセル以下になる岩は描かない。遠くの見た目は下地のテクスチャに任せる。
- 影: 今のカスケードシャドウに乗せる。影の描画では 1 段粗い LOD を使ってよい。

## インポスターは使わない（判断の記録）

2026-09-30 のユーザー判断で、岩アセットの最終段はインポスターにせず、粗いメッシュにする。理由は次のとおり。

- 岩場の見栄えは、岩どうしや地面とのめり込み・重なりで決まる。インポスターは奥行きを持たないので、接地や重なりが崩れる。
- 岩の輪郭は硬く角張っているので、方向の違う絵を混ぜるときの二重像が目立つ。
- 焼いた法線で光を当て直しても、落ち影や岩どうしの遮蔽が本物のメッシュと合わない。
- 岩は不透明でまとまった形なので、100〜200 三角形でも遠目には岩に見える。数千個でも数十万三角形で、節約の効果が小さい。

代わりに、遠景は「小さい岩を消して下地のテクスチャに任せる」ことと、後続の HLOD で扱う。

## 後続: HLOD と書き出し

- **HLOD**: 撒いた岩と下地をまとめて 1 つの粗いメッシュにし、見た目をテクスチャへ焼く。山全体を遠くから見るときは、岩 1 個ずつではなく、これ 1 つを出す。
- **書き出し**: 岩山 1 つを、配置情報つき（岩アセットの参照 + 行列の一覧）と、HLOD の 1 メッシュの 2 通りで書き出す。terrain-graph やゲームエンジンへ持ち込むのに使う。

## 段階

| 段階 | 作業 | 完了条件 |
| --- | --- | --- |
| A1 岩アセットを焼く | Rock Asset ノード（変種 1・LOD0 のみ。ノードと LOD の生成は 2026-09-30 に実装、保存は未実装）、付属フォルダへのメッシュとテクスチャの保存、Model ノードからの `.rockscene` の参照 | 岩グラフで焼いた岩アセットを、別のシーンの Model ノードで置いて、同じ見た目で表示できる |
| A2 LOD | UV を保つ簡略化、LOD の段と切り替えの大きさ（2026-09-30 に実装。付属フォルダへの保存は A1 と一緒に） | 4 段の LOD が同じテクスチャで継ぎ目なく表示でき、ビューポートで段を確認できる |
| A3 変種と古さの判定 | グラフ全体の Seed のずらし量、変種 N 個を焼く、ハッシュの記録 | Seed 違いの N 個が焼かれ、グラフを変えると「古い」と判定される |
| M1 山グラフの土台 | `.rockmountain` の保存・読込・Undo、グラフの種類の切り替え、Heightmap → Terrain Mesh | ハイトマップを読み、実寸の下地を材質つきで表示できる |
| M2 撒く | Terrain Mask（傾斜）、Rock、Rock Scatter、Instance Merge、Mountain Output、インスタンシング、LOD の選択 | 傾斜の強い所に、2 つ以上の岩グラフの変種が撒かれ、数千個でも操作できる速さで表示できる |
| M3 岩場らしさ | Scatter を分けた大・中・小の階層、避ける入力、層の向き、めり込み、高度と曲率のマスク | 参考写真と並べて、岩場として破綻がないことを複数の視点で確認する |
| M4 後続 | HLOD の焼き込み、書き出し | 別のビューア（または terrain-graph）で読み直せる |

A1〜A3 だけでも、既存の Model ノードで岩アセットを確かめられる。M1 以降は A1 の後なら着手できる。

## 決めていないこと

- 付属フォルダの名前と、メッシュの保存形式（独自のバイナリか glTF か）。
- テクスチャの量。変種ごとに 4 枚 × 2048² を持つと、変種 × 岩グラフの数で大きくなる。解像度の既定と、細かい模様をタイリングの詳細テクスチャで補うかは A1〜A2 で見積もる。
- ハイトマップの生成（ノイズなど）を山グラフに持つか、読み込みだけにするか。
- 今のボリュームの研究（岩グラフ側の改善）との優先順位。

## 対象外

- インポスター（上記の判断）。
- 数 km 規模の地形、地形の LOD、植生（terrain-graph の役割）。
- 物理的な落石や堆積のシミュレーション。
