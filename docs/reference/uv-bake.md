# 自動UV展開・UVビュー・材質ベイク

作成日時: 2026-09-21 18:50
更新日時: 2026-09-21 23:38

## 接続と操作

`Volume to Mesh → UV Unwrap → Material Bake → Mesh Output` の順につなぐ。Material BakeのMaterial入力へSurfaceを接続し、「ベイク実行」を押す。未ベイク・再ベイク待ちの間は元のSurface材質を表示する。Mesh OutputのMaterialを明示的に接続した場合はそちらを優先する。

UV Unwrapを選択すると、UVチェッカーでそのノードをプレビューする。別ノードを選択すると元のプレビューへ戻る。「Mesh Outputへ戻す」で明示的に表示を戻すこともできる。ビューポートと同じ列の「UVビュー」には、現在プレビューしているUVメッシュの0〜1領域と、島ごとに色を変えた三角形のワイヤーフレームを表示する。ホイールでズーム、中ボタンで移動、全体表示で初期化する。

チェッカーは `assets/textures/uv_checker.png`（2048×2048、16×16マス）を使用する。Houdiniの参考画像に合わせ、明るいマスに行名A〜P、暗いマスに列番号1〜16を表示する。天球やライト設定は変更せず、陰影・影・露出・トーンマッピング・被写界深度を通常どおり適用する。チェック中は照明付き表示を使い、元のチャンネル表示設定は保持する。表示専用の画像なので、材質やベイク結果には混ぜない。

## UV Unwrap

| 設定 | 範囲・意味 |
| --- | --- |
| テクスチャ解像度 | 128 / 256 / 512 / 1024 / 2048 / 4096から選択。UVを配置し、ベイク画像を生成する正方形の一辺 |
| 余白 | 1〜32 px。島の配置間隔とベイク画像の色の拡張幅 |
| 品質 | 1〜4。島の探索反復数。大きいほど計算が増える |

- xatlasを固定コミットで同梱する。ライセンスと出典は `third_party/xatlas/`。
- 旧シーンの任意解像度は読み込み時に次の2のべき乗へ切り上げる（例: 600→1024、範囲外は128〜4096へ制限）。解像度が変わったベイクは再実行が必要になる。
- 入力は生成した三角形メッシュ、上限50万三角形。Volumeは先にVolume to Meshを通す。インポートモデルのUV再展開は対象外。
- 入力の位置と三角形を保ち、面の各コーナーへUVを追加する。UV境界のために共有トポロジーを分断しない。描画時はUVに対応する接線と符号を生成する。
- 複数の生成メッシュを受けた場合は1個のメッシュ、1枚のアトラスへまとめる。同じ素材構成なら適用情報を引き継ぐ。異なる素材の枝は展開後に素材を適用する。
- SDF由来の微小面が無視されないよう展開用座標を正規化する。UV三角形の重なりも検査し、問題の面だけ別の島へ分けて再配置する。修復できない場合はエラーとし、不正なUVをベイクへ渡さない。
- 初回・入力形状・設定変更時は同期処理。変更のない入力はキャッシュを使う。大きなメッシュでは操作待ちが発生し得る。手動のシーム指定・島の編集・UDIMは未対応。
- UVビューは現在の出力のうち最初のUVメッシュを表示する。通常はUV Unwrapで1個へまとまる。

## Material Bake

Apply Materialから引き継いだ素材をベイクできる。任意のMaterial入力を接続した場合はそのSurfaceで全面を置換する。形状AOの生成・素材AOへの乗算にも対応。詳細は[素材の適用と形状AO](material-application.md)。

| PNG | 内容 |
| --- | --- |
| BaseColor.png | sRGBの色。照明や影を含めない |
| Normal.png | UV接線空間のDirectX法線 |
| RoughnessMetallicAO.png | R=Roughness、G=Metallic、B=AO |
| Height.png | 既存のHeightチャンネル |

既存プレビューと同じSurface合成器・Triplanar投影を用い、UV空間でGPU描画する。Triplanar法線はワールド方向からUV接線空間へ変換する。島の周囲に色を拡張してPNGへ保存し、生成材質をUV方式で自動適用する。

ルート内の `Bakes/MaterialBake_<ノードID>.../` へ実行ごとに別名保存する。シーン保存で生成材質を共有アセットとして記録し、画像参照と入力の指紋を保持する。Undo/Redoでベイク材質を戻せるよう、過去の画像は自動削除しない。

形状・UV・描画法線/接線・Surface設定・入力画像の内容から指紋を作る。現在の入力と一致しない場合、古いベイクを表示せず元の材質へ戻し「再ベイクが必要」と表示する。ベイクはボタン操作時のみ実行する。画像IDや絶対パスではなく内容を比較するので、保存・読み込み後も一致を判定できる。

初版は4枚とも8bit PNG。Heightの精度やHDR色の保持、Opacity、High/Low間の転写、ケージ、外部向け接線規約の保証、メッシュ書き出しは対象外。細いUV島・低解像度・強い縮小では模様のぼけや継ぎ目が残るため、必要に応じて解像度・余白を調整する。素材ベイクと画像保存は同期実行する。形状AOはGPUでフレーム間に分割して計算し、進捗率の表示とキャンセルに対応する。BVH構築はCPUで行う。

サンプルは [examples/uv-bake](../../examples/uv-bake/README.md)。

## 検証

- Debug/Releaseビルド、Release単体テスト、Debug CTest（1/1、48.34秒）が成功。
- 単体テストでBoxとSDFの両変換方式のUV、形状・面順序の保持、重なり、再現性、接線、入力エラー、キャッシュ、Material入力、出力側材質の優先、Undo/Redo、画像余白を確認。
- Release実画面でUVチェッカー選択/解除、UVビュー、画面のベイク実行ボタン、512と1024の4枚出力、保存と再読み込みを確認。保存前後のビューポート画像は一致した。
- 投影サイズ・生成Seed・UV余白をそれぞれ変え、再ベイク待ちと元材質への復帰を確認。512の強い市松模様では元材質とベイク材質のメッシュ周辺切り出しの平均RGB絶対差は1.59 / 0.94 / 0.62（255段階）。有限解像度と8bit量子化による差は残る。
- 検証素材は `build/uv-bake/validation/`、配布サンプルをコピーして試した結果は `build/uv-bake/sample-validation/`。
