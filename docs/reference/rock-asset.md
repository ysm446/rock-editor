# Rock Asset

作成日時: 2026-09-30 08:40
更新日時: 2026-09-30 17:39

## 位置付け

岩グラフの最終段。入力のメッシュから段階的な LOD（LOD0〜LODn）を作り、この岩グラフの岩アセットにする。全体の構想は [岩アセットと山グラフ](rock-asset-mountain-graph.md) の A1〜A2 にあたる。LOD の生成とビューポートでの確認、付属フォルダへ焼いて保存すること（下の「岩アセットを焼く」）まで実装した。変種（A3）と、山グラフからの参照（M2）は未実装。

```text
… → UV Unwrap → Apply Material → Material Bake → Rock Asset → Mesh Output
```

入力・出力とも Mesh 型。出力は LOD0 なので、Mesh Output へ繋げば今までどおり表示できる。1 つの岩グラフに 1 つだけ置く想定（複数置いても評価はできる）。右クリックメニューの「メッシュ（ポリゴン）」にある。

## 設定

| 項目 | 内容 |
| --- | --- |
| LODの段数 | 1〜6、既定 4。LOD0 を含む |
| LOD0の上限 | 64〜500,000、既定 20,000。入力がこれを超えるときだけ LOD0 を減らす。入力が複数のメッシュなら三角形数に応じて割り振る |
| LODnの割合 | LOD0 の三角形数に対する割合（%）。既定は 50 / 25 / 12.5 / 6.25 / 3.125 |
| LODnの切替 | 岩を包む球の直径が画面の高さに占める割合。これを下回るとその段にする（UE の Screen Size と同じ考え方）。既定は 0.5 / 0.25 / 0.12 / 0.06 / 0.03。表示だけに使い、LOD は作り直さない |
| LODnのUV共有 | その段が LOD0 の UV を共有するか。既定は LOD1 だけ共有、LOD2 以降は作り直す。外した段より下の段は押せない（共有しない）。下の「段ごとの UV」 |

保存名は `rockAsset`。保存・読込と Undo / Redo に対応。設定欄の固定欄に段ごとの実際の三角形数を出し、目標（割合から決まる数）より 5% 以上多い段があれば注意を出す。評価は別スレッドで行い、計算中は進み具合を表示する。

## 処理

1. 入力がモデル・ボリュームなら診断する（Volume to Mesh を挟む）。
2. LOD0: 入力が上限を超えるときだけ [Decimate](decimate.md) で減らす。
3. LOD1 以降: 1 つ前の段を Decimate で減らす（目標は LOD0 の三角形数 × 割合、最低 64）。
   - **UV を共有する段**: UV の島の境界を保ったまま減らすので、LOD0 と同じ UV を持つ。前の段が目標以下なら同じものを使う。
   - **UV を共有しない段**: 前の段から UV を捨てて減らし、その段だけで UV Unwrap し直す（下の「段ごとの UV」）。
4. Decimate は形のずれの上限を設けず（0）、稜線の保護は既定（1）。

出力の評価結果（`GeneratedRock::lods`）に全段を持ち、`mesh` は LOD0。先頭から何段が LOD0 の UV を共有するかを `GeneratedRock::sharedUvLods` に持つ。LOD0 が UV を持たないときは全段を「共有」として扱う（どの段も UV を持たない）。

### 材質とベイク結果

UV を共有する段には、Apply Material の素材・Shape Mask などの画像マスク・Material Bake の結果をそのまま貼れる。UV を共有しない段には、Material Bake の結果を LOD0 から転写したテクスチャを貼る（下の「段ごとの UV」）。

Material Bake の結果が「まだ使えるか」は、焼いたときのメッシュの指紋で判定している。LOD は形が違うので、Rock Asset は減らす前のメッシュ（`GeneratedRock::bakeMesh`）を残し、表示のときはその形で指紋を照らす。Rock Asset の下流にもう一度 Material Bake を置いた場合は、そのベイクの入力で照らす。

## ビューポート

Rock Asset を選ぶと、ビューポートにその出力を出す（選択を外すと元のプレビューへ戻る）。出している間は、表示モードのボタンの右に次を並べる。

```text
[表示モード] [表示]  [LOD 自動] [0] [1] [2] [3]  LOD1 · 2,100 三角形 · 画面 0.42
```

- **0〜n**: その段に固定する。
- **LOD 自動**: カメラから見た大きさ（上の「画面」の値）と「LODnの切替」で段を選ぶ。フライ操作（右ボタン + WASD）で近づいたり離れたりして、切り替わる所を確かめられる。
- 段を変えても評価し直さず、シーンも作り直さない。全ての段の GPU メッシュをシーンを作るときに送っておき（`SceneMesh::lodGeometries`）、描く段だけを変える（`PreviewRenderer::SetMeshSceneLod`）。以前は段を変えるたびにシーンを作り直していて、材質の評価と GPU への転送で引っかかっていた（2026-09-30 に直した。切り替えは 1 回 0.02 ms 以下）。
- ビューポートの統計の「メッシュ三角形」は、いま出している段の数になる。

### LOD の色分け

表示モードに「LOD（色分け）」を追加した（terrain-graph から移植。UE5 の LOD Coloration と同じ配色: LOD0 白、LOD1 赤、LOD2 緑、LOD3 青、LOD4 黄、LOD5 マゼンタ）。クレイと同じ陰影で、Rock Asset の LOD のメッシュだけベースカラーを段の色にする。LOD でないメッシュはクレイと同じ色。色分けのときは、LOD の番号のボタンの下端に段の色を引いて凡例を兼ねる。

## 開発用の起動引数

撮影・検証用に 2 つ足した。

- `--rock-asset-lod <n>`: LOD の出し方。-1 で自動、0 以上でその段に固定。
- `--view <番号>`: 表示モード（`renderer::DebugView` の数値。10 がクレイ、11 が LOD の色分け）。
- `--test-lod-switch`: 選んでいる Rock Asset の段をフレームごとに切り替え、そのフレームの `SyncMeshGraph` の時間をログへ出す。

例: `rock_editor.exe --root examples/rock-asset --project examples/rock-asset/rock-asset.rockgraph --select-node 80 --rock-asset-lod 3 --view 11 --screenshot-ui out.png`

## 岩アセットを焼く（2026-09-30）

設定欄の「岩アセットを焼く」で、シーンの付属フォルダ `<シーンのファイル名>.bake/`（`Boulder.rockgraph` なら `Boulder.rockgraph.bake/`）へ書く。シーンをルートの中へ保存してから使う（未保存ならボタンが押せない）。

| ファイル | 内容 |
| --- | --- |
| `asset.json` | 目録。形式 `rock-editor.rock-asset` 版 2、段ごとのメッシュのファイル名・三角形数・切り替えの大きさ・テクスチャのフォルダ、LOD0 の範囲、テクスチャの有無、内容のハッシュ |
| `lod0.rockmesh` … | 段ごとのメッシュ。独自のバイナリ（`geometry::Mesh` の位置・三角形・角の UV・島の番号・アトラス寸法をそのまま書く）。複数のメッシュは 1 つにまとめる |
| `BaseColor.png` / `Normal.png` / `RoughnessMetallicAO.png` / `Height.png` | Material Bake の結果（LOD0 の UV を共有する段で使う）。上流に Material Bake が無ければ書かない |
| `lod2/BaseColor.png` など | UV を共有しない段のテクスチャ（LOD0 から転写したもの、4 枚）。目録の段の `textures` が `lodN` を指す |

- 上流の Material Bake が未ベイク・古いときは、**先に Material Bake を実行してから**焼く。焼き終えたら、プレビューは焼く前に見ていたもの（Rock Asset の段）へ戻す（2026-09-30 から。以前は Material Bake へ移ったままだった）。
- 目録は最後に書く（`asset.json.tmp` から置き換える）。段を減らして焼き直すと、余分な `lodN.rockmesh` と、使わなくなった `lodN/` を消す。
- 版 1 の目録（段の `textures` が無い）は、全ての段が直下のテクスチャを共有するものとして読む。版 2 ではハッシュの作り方が変わるので、版 1 で焼いた結果は「古い」と出る。
- 読み込みは `io::LoadRockAsset`。付属フォルダが無い・壊れているときは「未焼成」として扱う。
- **付属フォルダはシーンの一部として扱う。** アセット欄でシーンの名前を変える・別のフォルダへ移すと付属フォルダも揃えて動かし、シーンを削除（退避）すると付属フォルダも一緒に退避する。付属フォルダはアセット欄にフォルダとして見える。

### 焼いた結果が古いか

設定欄に「焼いた結果: 未焼成 / 最新 / 古い」を出す。焼いたときの目録のハッシュと、いまの評価結果から同じ手順で求めたハッシュを比べる（`io::RockAssetHash`）。ハッシュに入れるのは、段ごとのメッシュ（位置・三角形・UV）、切り替えの大きさ、段のテクスチャのフォルダ、**Material Bake の入力の指紋**（いまの入力でベイクしたら付く指紋。ベイクしたかどうかではない）。Material Bake の結果は一時的で開き直すと消えるが、入力が同じなら「最新」のまま。

### 見送ったこと

計画では「既存の Model ノードで `.rockgraph` を選んで置けるようにする」としていた。`.model` は元のファイルをワークスペースの ID で参照する仕組みで、ここへ岩アセットを差し込むと改修が大きいので見送った。山グラフでは M2 の Rock ノードが付属フォルダを直接読む。

## 段ごとの UV（2026-09-30）

### 背景

LOD0 の UV を保ったまま減らすと、細かい段が目標に届かない。`data/Rock-Models/rock_flat_2` では LOD0 10,000 → LOD1 5,000 → LOD2 3,572 → LOD3 3,532 で頭打ちになった（目標は 2,500 / 500）。

- UV の島が 958 個あり、LOD2 では頂点の 98% が継ぎ目の上にある。3 つ以上の島が集まる頂点（約 1,260 個）は動かせず、島ごとに三角形が残るので、下限はおよそ 3,000。
- 島が多いのは形のせい。1〜2 三角形の島は稜線や折れた所の面で、隣の面と大きく向きが違う。xatlas は法線が 60° 以上ずれた小島をまとめない（固定の条件）ので、xatlas の重み（`maxCost` など）を変えても島は約 930 にしか減らない。条件を緩めても 793 島・下限 2,998 だった。
- UV を持たせずに形だけ減らすと 924 まで下がる（10,000 の 9%）。そのあと展開すれば、島の数は Decimate の下限に関係しない。

UV に無理をさせないため、段ごとに UV を作り直せるようにした（ユーザー判断）。

### 設定

段ごとの「LODnのUV共有」（`RockAssetSettings::shareUv[level]`。LOD0 は常に共有。保存名 `shareUv`）。

- **共有する段**: 今までどおり UV を保って減らし、Material Bake のテクスチャをそのまま使う。
- **共有しない段**: 1 つ前の段から UV を捨てて減らし、その段だけで UV を展開し直し、その段のテクスチャを LOD0 から転写する。
- 共有しない段より下の段も共有できない（LOD0 の UV を持たない形から減らすため）。チェックは押せなくなる。実際に共有する段の数は `RockAssetSharedUvLods`。
- 既定は LOD1 が共有、LOD2 以降が作り直し。保存に `shareUv` の無い古いシーンもこの既定になる。

### 作り直す段の UV とテクスチャ

- **UV**: `UnwrapMesh`（余白 4 px、品質 1）。解像度は LOD0 のアトラスを段ごとに半分にしたもの（最小 128）。例: LOD0 2048 → LOD2 512 → LOD3 256。
- **テクスチャは LOD0 から転写する**（`geometry::TransferTextures`）。その段の UV の画素ごとに、`TransferDetail` と同じようにその段の面から LOD0 へレイを飛ばし、当たった LOD0 の点の UV で LOD0 の 4 枚（Material Bake の結果）を双線形に読む。
  - BaseColor・RoughnessMetallicAO・Height: そのまま写す。
  - Normal: LOD0 の接線空間の法線を LOD0 の角の向きでワールドへ戻し、その段の接線空間で表す。LOD0 の形の凹凸が法線マップに入るので、減らした段でも陰影が残る。
  - 探す距離（ケージ）は LOD0 の大きさの 5%。当たらなかった画素が 1% を超えたら、その画素だけ距離を 3 倍にして探し直す（2 回まで）。それでも当たらなかった画素はエッジパディング（`FillBakeBackground`）で周りから埋める。
- `TransferDetail` と `TransferTextures` は、画素ごとにレイを飛ばす処理（`Trace`）を共有する。CPU で行ごとに並列。
- 上流に Material Bake が無い・未ベイク・古いときは転写しない。表示は LOD0 と同じ材質のままにする（UV で貼る素材は段ごとにずれる）。

### 表示・保存・撒く

- **ビューポート**: UV を共有する段は今までどおり 1 つの `SceneMesh` で切り替え、UV を共有しない段は、その段の形と転写した材質を持つ別の `SceneMesh` にしてシーンの末尾に並べる。`SceneMesh::lodRange` で描く段を決めるので、段の切り替えではシーンを作り直さない。転写した画像は `Application::m_lodTextures` に一時テクスチャ・材質と一緒に持つ（キーは LOD0・その段のメッシュ・ベイクの指紋のハッシュ）。使われなくなったら `SyncMeshGraph` が捨てる。
- **焼く**: 共有する段のテクスチャは今までどおり付属フォルダの直下へ置く。作り直した段は `lodN/` に 4 枚を置く。目録の段ごとに `textures`（空か `lodN`）を持たせる。
- **Rock Scatter**: テクスチャのフォルダごとにスロットを分け、スロットごとに材質を持たせる（`ModelPreview` はスロットで材質を引くので、描画の仕組みは変えていない）。

### 残る課題

- UV を持たない Decimate でも、`rock_flat_2` は 892〜924 で止まる（リンク条件・面の裏返り・細長い三角形で縮約を断る）。5% のような目標まで下げるには別に調べる。
- そこまで減らした段（`rock_flat_2` の LOD3、892 三角形）は、薄く尖った面や折れ目が出る。転写ではなく Decimate の形の質の問題。
- 転写した Height は LOD0 の値をそのまま写す。LOD0 とその段の形の差をハイトへ足すかは、使い道（視差・変位）が決まってから考える。
- 岩が複数のメッシュのとき、UV を共有しない段はメッシュごとに展開するのでアトラスが重なる。Material Bake は 1 つのメッシュしか焼かないので、そのときはテクスチャを書かない。

## 制限

- 焼くのは同期実行（重い上流があると、その評価の間はアプリが止まる）。
- 変種（Seed のずらし）は未実装。
- 段と段の間は即座に切り替わる（重ねて移るフェードは無い）。
- UV を共有する段では、継ぎ目の頂点が 3 つ以上の島の集まる所は動かさないので、島が極端に多いと目標に届かないことがある（設定欄に注意が出る。その段の「UV共有」を外す）。
- UV を共有する段には LOD0 の細部の法線を転写しない（Material Bake の法線マップを共有するだけ）。UV を共有しない段は、LOD0 の形の凹凸も法線マップへ転写する。

## 検証

`tests/RockAssetTests.cpp`。Base Shape（丸めた箱）→ UV Unwrap → Rock Asset で、既定の 4 段ができること、上限以下の入力なら LOD0 が入力そのままであること、段ごとに三角形が減ること、全段が同じアトラスの有効な UV を持ち閉じた 1 成分であることを確認する。切り替えの大きさの変更では作り直さず、段数と LOD0 の上限の変更では作り直し、LOD0 も UV を保って減ること、Material Bake の下流ではベイク元と照合用のメッシュを引き継ぐこと、Model を繋げないことを確認する。

実アプリでは `examples/rock-asset/`（uv-bake のサンプルに Rock Asset を挟んだもの）で、固定の段の切り替え・クレイ・LOD の色分けと凡例を画像で確認した（`build/rock-asset-validation/`）。

焼く処理は `tests/RockAssetIoTests.cpp`（目録とメッシュの往復、ハッシュの変わり方、段を減らしたときの掃除、壊れたメッシュ、未焼成、改名・移動・退避で付属フォルダが揃うこと）。実アプリ（RelWithDebInfo）では `examples/high-low-bake/` の写しで `--bake-asset 80` を使い、Material Bake が先に走ってから 4 段（2,000 / 1,000 / 500 / 250 三角形）とテクスチャ 4 枚が書かれること、開き直しても「最新」、LOD3 の割合を変えたシーンでは「古い」になることを確認した。「岩アセットを焼く」ボタンは実マウスで未確認。

開発用の起動引数 `--bake-asset <node>` を足した（読み込み後にその Rock Asset を焼く。`--save-project` はその完了を待つ）。

段ごとの UV（2026-09-30）: `tests/RockAssetTests.cpp` で、既定では LOD0〜1 が同じアトラス、LOD2 以降が自分の 128 のアトラスを持ち目標の三角形数まで減ること、全て共有にすると全段が同じアトラスになること、共有しない段より下が共有しないことを確認した。`tests/DetailTransferTests.cpp` で、同じ UV への転写で色と法線がそのまま写ること、別の UV の球へ一定の値と真上の法線が写ること、UV の無い転写元・欠けた画像を断ることを確認した。`tests/RockAssetIoTests.cpp` で、段のテクスチャのフォルダの往復、欠けたときの扱い、不正な名前、掃除、版 1 の目録の読み込みを確認した。

実アプリ（Release）では `rock_flat_2.rockgraph` の写し（`data/test/lod-uv/`）で `--bake-asset 358 --rock-asset-lod 2/3` を使い、LOD0 10,000 / LOD1 5,000 / LOD2 2,500 / LOD3 892 三角形になり、`lod2/`（512²）と `lod3/`（256²）に 4 枚ずつ書かれること、転写で当たった画素が 99.8%（1 回目の距離だけでは LOD3 が 87%）であること、LOD2・LOD3 の表示に転写したテクスチャが貼られることを画像で確認した（`build/lod-uv-validation/`）。チェックボックスの実マウスの操作と、山グラフの Rock Scatter で段ごとの材質が出ることは未確認。
