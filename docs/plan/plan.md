# plan — v2 仕様に基づく実装計画

作成日時: 2026-09-20 20:05
更新日時: 2026-09-20 23:40

## 方針

[v2 原仕様](../rock_generator_spec_v2.md) の §§48–53 を軸に、既存アプリへ機能を追加する。旧計画の完全分割優先を改め、有限亀裂と Rock Bridge の検証を先に置く。CPU / Mesh を第一段階とし、SDF や物理ソルバは後続とする。

既存ノードグラフは最初から使う。原仕様 M9 はグラフ新設ではなく、一連の岩生成ノードとキャッシュを仕上げる工程として扱う。各段階に設定 UI・保存/読込・Undo・テストを含める。

## 次の実装単位

P5 の母岩4形状と弱い BaseNoise を実装した（P5 前半）。曲面の生成・平面分割と seed の再現性を検証済み。Joint Set のパッチ列生成・複数系統のガイド表示も実装した。次は P5 後半の多片分割。外観は [参考写真との対応](../reference/visual-target.md) で比較する。

1. Joint Set の方向・間隔・ばらつき・本数・seed、パッチ列の生成とプレビュー・保存は完了。表示から実分割へ接続する。
2. 複数の平面から多片を生成する評価と Chunk ID/接続情報を拡張する。複数断面ループ・極小片・上限を検証する。
3. 曲面と交差パッチの部分切断を拡張する。完全分割だけで有限亀裂の対応完了とはしない。
4. 2～3系統の節理を組み合わせ、参考写真の主稜線と割れ目を無地で比較する。細かい分岐亀裂・剥離は別途必要量を判断する。

### P5 Joint Set ガイド（完了）

- 1～64本の有限パッチ列、中心/向き/オフセット、間隔とばらつき、共通の深さ・Persistence・Aperture。
- 直列接続で複数系統を重ね、合流時は生成元とパッチ番号で重複を除く。設定 UI・保存・Undo に対応。
- 母岩の実形状は維持する。Fracture は引き続き独立した単一平面で分割する。Joint Set の全平面を使う多片分割、交差部分亀裂、continuity/roughness は後続。

### P5 前半（完了）

- Box / RoundedBox / Sphere / Ellipsoid と分割数、丸み、弱い BaseNoise を実装。
- 閉じた共有頂点メッシュ、外接寸法、解析曲面と体積、ノイズの決定性と変位上限を検証。
- 曲面/ノイズ付き母岩から P4 の単一平面分割、保存・読込・Undo/Redo を確認。
- P3 の部分切断はノイズなし Box のみ。Joint Set・交差亀裂・多片分割を含む P5 全体は未完了。

### P4 の実装単位（限定範囲で完了）

1. `Fracture` ノードで完全分割を明示的に指定し、部分切断の状態とは区別する。入力は未分割の岩1個、単純断面1本。Crack の実形状を受けて独立した平面で分ける。
2. 平面による分割と切断面の生成を実装し、2つの閉じたメッシュ、外向き法線、分割前後の体積を検証する。
3. Chunk の ID・親・状態と分割面の接続情報を保持する。Locked は物理計算せず明示フラグにする。
4. 色分け・個別選択・移動・回転を接続し、設定と生成 ID の再現、Undo/Redo を検証する。選択自体の保存復元は P6。

部分切断の Depth/Persistence を上げただけで完全分離へ切り替えない。P3 の軸制約を越える一般メッシュの部分切断は別の拡張として残す。

### P3 の実装単位（限定範囲で完了）

- 直交する境界平面で Box を区切り、有限の切り込みを厳密に除去する。汎用の交線挿入・局所再三角形化は未実装。
- 開口・側壁・終端を持つ閉じた1連結体と、奥の未破断断面を生成・検証する。
- 未加工 Box 1個、軸に沿う向き、切り込み1回に限定。対応外を診断する。

### P2 の実装単位（完了）

- 中心・回転・半幅・深さ・persistence・aperture と表示フラグの設定・保存。
- 半透明の有限範囲/到達範囲表示、数値による移動・回転、Undo/Redo。
- 座標系・境界値・入力形状の維持・表示切り替えのテスト。

### P0/P1 の実装単位（完了）

1. Debug ビルド、既存 CTest、起動を確認し、基盤の問題を記録する。
2. geometry/ に CPU メッシュ、AABB、法線生成、閉包・体積・連結性の検証を追加する。
3. Base Rock の Box 設定と評価を既存 NodeSettings / 定義テーブルへ追加する。
4. renderer::MeshData への変換を用意し、Mesh Output と途中プレビューから描画する。
5. 寸法・seed の UI、ProjectIo、Undo を接続し、保存後の Box 再現を確認する。

P2/P3 の検証結果と対応範囲は [進捗](progress.md) に記録する。

## 技術上の検証関門

P3 は軸に沿う単一 Box の方式を検証済み。任意角度・一般メッシュへの拡張は依然として大きな不確実性がある。無限平面クリップだけでは有限亀裂と Bridge を作れない。最初は Box 表面から入る有限幅の単一切り込みを対象とし、交線の挿入・局所再三角形化・亀裂壁と終端の閉包を試作する。正の幅で形状と連結性を確かめ、幅ゼロは潜在亀裂のメタデータ/デバッグ表示として区別する。

P3 の限定範囲では閉包・連結性を確認したため P4 へ進める。対応範囲を拡張するときは同じ検証条件を満たすまで完了としない。P5 で曲面と複数パッチの交差へ広げる。線や色によるパッチ表示だけでは部分亀裂の完成としない。

完全分割では頂点上・辺上・同一平面、極小片、複数切断ループを検証する。不正形状を下流へ渡さず、対象ノードと原因を表示する。Chunk 数・三角形数には上限と診断を設け、具体値は P5 の測定で決める。

## 原仕様内の段階差の整理

- §12 の Secondary Fracture は Stage C、§49 は Post-MVP。初回 MVP は一次破断を優先し、Secondary Voronoi / 再帰破砕は後続とする。
- §26 は低周波の破断面ノイズを MVP、§49 は fracture surface noise を Post-MVP とする。P4 は平面で成立性を確認し、低周波ノイズは P7 の追加候補とする。MVP 必須にするかは閉包と両側の整合を検証して決める。
- Groove / Erosion は全体フローにはあるが M0–11 にはない。独立ノードは MVP 後、有限亀裂の基盤は MVP に含める。
- OBJ は M0–11 にないが §45 の MVP 要件なので P8 に含める。
- §44 の JSON version: 2 は例。現在の保存版は1であり、実際の変更と互換方針に応じて更新する。

## MVP 後

4. 接触・摩擦・重力による Locked 判定、Terrain Editor との連携。

予定日は置かず、各段階の受入結果で進める。[設計整理](../reference/architecture.md) と [検証計画](../reference/validation.md) を判断基準にする。
