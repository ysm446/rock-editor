## 方針

固定座標の積層に対し、上下面の投影交差面積を支持として記録する。Peelは全層共通で1片ずつ削除し、両面を覆われた中間層を保護する方式に更新。普段のUIは進行・ばらつき・別の欠け方を中心にし、詳細設定は折りたたむ。[仕様](../reference/piece-erosion.md)。以下の上下支持を後続とする記述は初期段階の経緯として残す。

2026-09-26の追加依頼により、Peelの操作を「欠けの進行」を中心に整理。最上部の進行スライダーと近接したばらつき・Seedで、同じ欠け方を前後させて調整する。自動再生は後続の検討とする。

2026-09-26の追加依頼により、Voronoi分割の共有面からピース間の隣接ID・面積を保持し、Piece Select / Peelで露出した外周から内側へ段階的に選択する処理を追加。まず同じ板の内部の接続を扱い、上下の板の重なりによる支持は後続にする。[仕様](../reference/piece-erosion.md)。

2026-09-26の追加依頼により、Piece Select の選択色・削除後比較・層別の表示を改善し、積層の外側から指定層数の側縁を選ぶ処理と内側への減衰を追加する。今回の判定は層順序によるもの。板同士の重なりから張り出した部分を求める露出判定と、削除後の新しい外周への反復侵食は後続とする。

2026-09-26の追加依頼により、薄板をメッシュで生成・分割し、外周を欠いてから必要に応じてボリューム化する流れを優先する。Layered Boxes と Pieces 入力の Scatter / Voronoi、層指定と Rim 選択を実装した。[仕様](../reference/layered-pieces.md)。次は実物との比較から面のうねり・局所剥離を検討する。下記のボリューム先行の予定よりこの方針を優先し、既存の Parallel Planes / Volume Crack は利用可能な経路として残す。

2026-09-22の依頼により、ライティング設定から切り替えるGPUスクリーンスペースAOを追加。表示専用とし、素材AOと形状AOベイクのデータは変更しない。

2026-09-22のユーザー依頼により、Apply Materialの後段へSubdivideとDisplaceを追加する。GPUで合成したハイトを使い、共有頂点とUVを保持して実メッシュを変位する。上限・取消・保存/Undoと下流のUV/AOベイクを含む。[仕様](../reference/displace.md)。

[v2 原仕様](../rock_generator_spec_v2.md) の §§48–53 を軸に、既存アプリへ機能を追加する。旧計画の完全分割優先を改め、有限亀裂と Rock Bridge の検証を先に置く。CPU / Mesh を基本とする。2026-09-21 のユーザー指定により、直方体集合からの CPU ボリューム変換を先行する。汎用 SDF や物理ソルバは後続とする。

既存ノードグラフは最初から使う。原仕様 M9 はグラフ新設ではなく、一連の岩生成ノードとキャッシュを仕上げる工程として扱う。各段階に設定 UI・保存/読込・Undo・テストを含める。

2026-09-26のユーザー依頼により、構造を決めてから割る初版として `Parallel Planes` と `Volume Crack` の Planes 入力を追加。向き・実寸の間隔・位置・間隔のばらつき・Seed と選択時ガイドを持つ。旧 Points 入力を維持し、2系統は Volume Crack を直列にして組み合わせる。[仕様](../reference/parallel-planes.md)。次は有限範囲の局所剥離を試し、Volume Terrace の置き換え・役割の変更を判断する。今回の順序を以前の「柱状節理から」の候補より優先する。

ユーザー指定により、Apply Materialを1種類のノードとして追加。マスク未接続は全面置換、接続時は素材の積み重ねとする。生成Meshに適用情報を引き継ぎ、既存Material Bakeへ形状AOを追加する。[素材の適用と形状AO](../reference/material-application.md)を参照。

2026-09-21の追加依頼で、メッシュ方式のVoronoi分割とピース選別・個別操作を新規設計した。仕様は [Voronoiとピース操作](../reference/voronoi-pieces.md)。旧Crack / Fractureは復活させず、新しいPoints / Pieces / Selection型で処理を分ける。Base Rockの表示名をBase Shapeに変更し、保存用の `baseRock` は維持する。

次の実装順はV1（Box/凸立体の幾何核）→V2（グラフ・色分け・保存・非同期評価）→V3（選別・削除・抽出）→V4（個別操作・UV/ベイク接続）。V1〜V4を画像の工程を再現する初版とする。V5で凹形状・空洞・SDF由来の一般メッシュへ広げる。この順序を下記の過去のP計画より優先する。V1〜V4の初版を実装した。6ノード、色分け、選別、個別変換とギズモ、非同期評価、UV/ベイク接続が利用できる。サンプルは `examples/voronoi-pieces/`。V5の一般メッシュ対応は未着手。

2026-09-21 のユーザー判断により、Joint Set / Crack / Fracture ノードを削除した。`src/crack/`・`src/fracture/`・亀裂ガイド描画・Chunk の選択とギズモ・関連テストも取り除いた。旧シーンに残るこれらのノードは、読み込み時に未知の種類として接続ごと捨てる。下記 P2～P5 の記述は削除前の履歴として残す。

2026-09-21の追加依頼により、生成メッシュへの材質適用とTriplanarを先行する。SurfaceをMesh Outputへ接続し、UV展開なしで形状編集中の材質を確認する。続くユーザー依頼で、後段のUV Unwrap、選択時のチェッカー、同列タブの2D UVビュー、Material Bakeを追加する。ベイクは手動実行し、上流変更時は再ベイク待ちとして元材質を表示する。仕様は [Triplanar](../reference/triplanar.md)、[UVとベイク](../reference/uv-bake.md)。

2026-09-21 のユーザー指定により、しばらくこのリポジトリをボリューム表現の研究の場として使う。当面は密な配列に持つ SDF のまま、ボリューム上の操作をノードとして増やし、実画面で試して判断する。OpenVDB の導入は、解像度128超（2026-09-22 に密な配列のまま上限を 96 → 128 へ引き上げた）・レベルセットのフィルタ・任意メッシュの取り込み・`.vdb` 書き出しのいずれかが必要になった時点で検討する。

- 追加済み: `Volume Transform`（移動・回転・拡大。格子の再サンプル）。
- 追加済み: `Volume to Mesh` の方式選択。2026-09-21のユーザー依頼で Dual Contouring の比較を前倒しし、従来の Marching Tetrahedra と同じSDFから比較する。適応格子・簡略化は対象外。
- 追加済み: `Volume Boolean`（和・交差・差、なめらかさ）。仕様は [Volume Boolean](../reference/volume-boolean.md)。
- 追加済み: `Plane Cuts`（平面の群による面取りと欠け。全体 / 局所、等方 / 主方向）。仕様は [Plane Cuts](../reference/plane-cuts.md)。Field 型は入れず、単体のノードとして実装した。
- 追加済み: `Volume Crack`（点の群の Voronoi 境界に沿う割れ目。V 字の断面、割れ目ごとのばらつき、ゆらぎ）。仕様は [Volume Crack](../reference/volume-crack.md)。幅のゆらぎはノード内のノイズで持ち、Field 型は入れていない。
- 追加済み: `Volume Noise`（なめらか / セル状 / 小面のノイズで表面を削る。歪みで平面と直線的な割れ目を崩す）。仕様は [Volume Noise](../reference/volume-noise.md)。
- 追加済み: `Volume Smooth`（ガウスぼかしでなまらせる / 角を立てる。上向きの面に集中できる）と `Volume Terrace`（層状の段を刻む）。仕様は [Volume Smooth](../reference/volume-smooth.md)、[Volume Terrace](../reference/volume-terrace.md)。2026-09-22 のユーザー依頼で追加。設計メモの 5 と、4 の Terrace。面の向きによる量の変化は Field 型ではなく、ノード内で入力の勾配から求める形にした。
- 追加済み: `Volume Close`（外から見えない隙間を埋める。遮蔽率で判定する「遮蔽」と、幅で判定するクロージングの「幅」。割れ目の奥の見えない壁にメッシュを作らないため）。仕様は [Volume Close](../reference/volume-close.md)。2026-09-22 のユーザー依頼で追加。
- 追加済み: `Volume Edge Wear`（凸な稜線と角だけを削る角の摩耗。ぼかした距離場と元の差を稜線の強さとし、最も近い表面の点で読む）。仕様は [Volume Edge Wear](../reference/volume-edge-wear.md)。2026-09-22 のユーザー依頼で追加。Mesh のベベルではなく Volume 側で持つ（Volume to Mesh の出力には稜線の折れ線が無いため）。稜線マスクを Volume Noise に「稜線に集中」として転用する案は未着手。
- 追加済み: `Remesh`（等方リメッシュ。辺の長さを揃え、稜線を保つ。UV を引き継ぐので UV Unwrap の後に置け、展開を重くせずに Subdivide なしで均一な Displace ができる）。仕様は [Remesh](../reference/remesh.md)。2026-09-22 のユーザー依頼で追加。マスクで場所ごとに辺の長さを変える適応リメッシュは未着手。
- 追加済み: `Decimate`（QEM による三角形の削減。UV Unwrap の前に置く）。仕様は [Decimate](../reference/decimate.md)。設計メモの 7（High → Low の法線ベイク）の前提になる。
- 追加済み: `Shape Mask`（UV付きの Mesh から形状に応じた材質マスクを作る。種類はオクルージョン / 上向き度 / 高さ。選択時はマスクを貼ってプレビュー）。仕様は [Shape Mask](../reference/shape-mask.md)。設計メモの 6。ユーザー判断により、種類ごとの専用ノードではなく、1つのノードの中で種類を選ぶ形にし、Mesh（UV付き）を明示的な入力にした。マスクはUV空間の画像で、既存の画像マスクの経路に乗る。Field 型は入れていない。
- 追加済み: `Mask Combine`（2つのマスクを画素ごとに合成。乗算 / 最大 / 最小 / 差 / 混合と、下限 / 上限 / ガンマ / 反転）。仕様は [Mask Combine](../reference/mask-combine.md)。2026-09-22 のユーザー判断で、Shape Mask の種類を組み合わせるための専用ノードとして追加した。対象は UV 空間の画像（Shape Mask / Mask Combine）に限り、Material Mask は初版では受けない。Field 型は入れていない。
- 2026-09-22 のユーザー依頼で、参考画像のような岩に必要な処理を [設計メモ](../reference/rock-shaping-nodes.md) に整理した。形を作る 1〜5（Boolean / Plane Cuts / Crack / Noise / Terrace / Smooth）とマスクの合成は実装済み。次の候補は、Shape Mask の種類の追加（曲率 / 切断面）→ ディテールの焼き込み。Field（スカラー場）型は、マスクの合成やボリューム側の変調が必要になった段階で改めて判断する。
- 予定（2026-09-22 のユーザー依頼）: `Volume Crack` の割れ目の源を Points 以外にも広げる。 検討の詳細（入力の候補、柱状節理などの割り方、複数 SDF、片理面の岩の作り方）は [Volume Crack の入力の拡張と割り方の候補](../reference/volume-crack-sources.md)。割れ目は「境界面までの距離」で彫るので、面が定義できれば同じ枠で割れる。候補は次の順。
  - Pieces 入力: Voronoi Fracture の分割片の切断面（`faceOrigins` が 0 の三角形。Piece の `transform` を適用）までの距離で彫る。Voronoi Fracture の回転・伸長がそのまま効き、方向性のある割れ目になる。割れ目ごとの幅の倍率は切断面の平面のハッシュで決める。
  - Mesh 入力（板ポリゴン）: 手で置いた平面や曲面の三角形までの符号なし距離で彫る。三角形までの距離は `MeshToVolume` の走査を流用する。
  - 分割の種類の追加: 柱状節理（軸に垂直な面の 2D Voronoi を軸方向に押し出し、柱ごとに高さのずれた横節理）、層状（平行平面群。間隔のばらつき、傾き、うねり）、直交節理、同心状、放射状。柱状と層状を先に扱う。
  - 線分（ワイヤーフレーム）入力は線に沿った溝になり用途が違うので、面ベースの後に必要なら検討する。
  - ノードの形はノード設計の好みに合わせ、「源」の種類を選んで種類ごとの入力ピンと設定を出す。V 字断面・ばらつき・ゆらぎ・空洞の埋め戻しは共通で使い回す。
- その他の候補: 平面を境に片側だけずらす断層ノード、軸ごとの倍率。Volume Terrace への「層ごとの面内のずれ」（片理面の岩のように板が斜めにずれて重なる形のため）。
- ノードの右クリックメニューは扱う型ごとに分ける（メッシュ / ボリューム / モデル / 共通 / 材質）。

## 現在の実装単位 — 単純な直方体の塊から始める

2026-09-21 のユーザー指定により、まず `Random Boxes → To Volume → Volume to Mesh → Mesh Output` を作る。少数の直方体を重ねて塊を作り、それをボリュームへ変換する。溝・複雑な破砕・材質を追加する作業は保留する。

1. **Random Boxes**：1～32個の直方体を Seed で生成。基準寸法、サイズばらつき、配置の広がり、各軸の回転幅を調整。追加 Box の中心を最初の Box 内に置き、ばらばらにならない塊とする。
2. **To Volume**：Mesh 入力の和集合を内外の符号を持つ3次元グリッドに変換。解像度16～96（最長辺のセル数）。下流へは Volume としてグリッド本体を渡す。独立した Volume to Mesh ノードで表面を Mesh 型に変換する。
3. **実際に試す**：右クリックメニュー、設定、保存/読込、Undo/Redo、変換前後のプレビューを接続。サンプルで Seed・回転・解像度と複数視点を比較する。
4. **次の判断**：この単純な塊をユーザーが確認した後、形の調整やボリューム上の平滑化など、必要な処理を決める。写真らしい外観を達成したとは扱わない。

To Volumeはユーザー指定により閉じたMesh入力へ拡張済み。Random BoxesはMesh出力とし、解析距離の高速経路を保持する。Base ShapeやPieces to Meshも入力できる。Modelの直接変換、VDB保存、Sparse Grid、平滑化は含めない。手順・制限は [直方体とボリューム](../reference/box-volume.md) にまとめる。

## 技術上の検証関門

P3 は軸に沿う単一 Box の方式を検証済み。任意角度・一般メッシュへの拡張は依然として大きな不確実性がある。無限平面クリップだけでは有限亀裂と Bridge を作れない。最初は Box 表面から入る有限幅の単一切り込みを対象とし、交線の挿入・局所再三角形化・亀裂壁と終端の閉包を試作する。正の幅で形状と連結性を確かめ、幅ゼロは潜在亀裂のメタデータ/デバッグ表示として区別する。

P3 の限定範囲では閉包・連結性を確認したため P4 へ進める。対応範囲を拡張するときは同じ検証条件を満たすまで完了としない。P5 で曲面と複数パッチの交差へ広げる。線や色によるパッチ表示だけでは部分亀裂の完成としない。

完全分割では頂点上・辺上・同一平面、極小片、複数切断ループを検証する。不正形状を下流へ渡さず、対象ノードと原因を表示する。Chunk 数・三角形数には上限と診断を設け、具体値は P5 の測定で決める。

## 原仕様内の段階差の整理
